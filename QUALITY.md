# ClipKit — Quality Scorecard

Scored under The Elite Software Master Prompt v1.1, §17. Every score names its evidence; a score without evidence would be a Fail. This file is updated in the same change as the work it scores.

**State at v0.1.0: total 84.6/100 — every dimension passes (none below 3, no Fail), and the weighted total sits 0.4 under the ≥85 release bar.** The gap is named, not rounded away: two recorded waivers (Performance and Scalability measurements) plus Correctness held at 4 because the Windows clipboard runtime is Unverified until a field pass. The field pass and one recorded benchmark close the gap (see "What moves the score"); no dimension's evidence is inflated to reach the line early.

| Dimension | Score (0–5) | Verdict | Evidence |
|---|---|---|---|
| Correctness (weight 14) | 4 | Pass | Full WinDevKit gate green locally (fmt, clippy both targets with `-D warnings`, all 25 host tests): both spec parsers (including the timeout cap and both sequence-number spellings), JSON shaping, and the wait decision loop against a scripted fake source with exact sleep scripts. Not 5: the Windows clipboard path itself (open/read/write/HDROP walk) compiles and type-checks for `x86_64-pc-windows-msvc` but has not run on a real Windows machine yet — the integration test runs on Windows CI and a field pass is still owed. |
| Security & privacy (12) | 5 | Pass | Zero dependencies; no network, no telemetry; the kit reads clipboard contents only when its caller calls, returns them only to that caller, and keeps no copy (stateless); the spec parser rejects duplicate keys and caps nesting depth (family JSON engine); spec sizes are bounded by the caller's own input. |
| Robustness (11) | 4 | Pass | Clipboard opens retry 10 × 10 ms against contention and close via RAII on every path; format-vanished races read as successful empty results instead of errors; set_text allocates before opening so failures leave the clipboard untouched, and frees its block only on paths where the ownership hand-off provably did not happen; every FFI entry point is catch_unwind-guarded. Not 5: the contention drill (another holder across a call) and fault injection on the set_text failure paths have not been run as a set. |
| Feature completeness (9) | 5 | Pass | Every row in `docs/PARITY.md` is Complete or Partially Verified with named evidence; the frozen v0.1 surface (text get/set, files get, sequence, wait) is fully implemented, and the Windows-only rows are marked Partially Verified rather than claimed. |
| Performance (8) | 3 | Waiver | The change check is one counter read (no clipboard open, no allocation); the wait loop sleeps between checks at 25 ms and never busy-spins; text/file reads copy each item once. Waiver: no benchmark has been measured yet — no timing figure is claimed anywhere; follow-up — record a wait-latency and large-text read figure alongside the field pass. |
| Maintainability (7) | 4 | Pass | `AGENTS.md` records the load-bearing contracts (ownership transfer and its exact free paths, allocate-before-open, guard-only clipboard access, equality-only sequence comparison, no-open wait design) with the reasons; module split is pure core / JSON / FFI / platform, with the wait logic injected so it stays testable; header, README, ROADMAP and PARITY are current with the code. |
| Modularity (6) | 5 | Pass | Everything is a stateless operation (`get_text`, `set_text`, `get_files`, `sequence`, `wait_change`); spec parsing, result shaping and the wait loop are pure functions unit-tested without the FFI or any OS call; the platform module holds every Win32 declaration and nothing else does. |
| UX & accessibility (6) | 4 | Pass | For a C ABI the surface is the UX: two small JSON shapes in, three out, "missing format is an empty result, not an error" removing the classic ambiguity, plain-language header documenting every export and contract, specific last-error messages (including the contention case naming its likely cause). Not 5: no worked example program ships in the repo yet (README's C example is the guide). |
| Scalability (5) | 3 | Waiver | No retained state exists to grow: the kit holds nothing between calls, and a wait is bounded by its capped timeout. Waiver: very large clipboard payloads (multi-hundred-MB text) have not been exercised; follow-up — one large-payload read recorded with the field pass. |
| Idiomatic quality (5) | 5 | Pass | `cargo fmt --check` clean and clippy `-D warnings` clean on host and `x86_64-pc-windows-msvc` targets in the local gate; zero dependencies; edition 2021 / rust-version 1.80 as per the family skeleton. |
| Test & corpus evidence (5) | 4 | Pass | 25 host tests, deterministic by construction (the wait loop runs on a scripted source and recorded fake sleeps — no real time passes), plus a Windows-only integration test with a graceful skip for clipboard-less sessions. Not 5: line-coverage percentage is not measured by tooling, so the 85%/70% floors are adopted targets, not verified facts — and the Windows paths add runtime surface no local test can reach. |
| Self-documentation (4) | 5 | Pass | Crate docs state the ownership, contention, missing-format and sequence-comparison contracts where the code lives; the set_text hand-off and its free paths carry the reasoning in comments at the point of decision; the platform module documents why every extern block carries its #[link]. |
| Documentation (4) | 4 | Pass | README with TL;DR, C example, honest caveats (polling latency, blocking wait, zero-counter ambiguity, synthesis limits, unbounded payload size); header documents every export; ROADMAP separates planned from explicitly not planned, including the privacy reasoning for excluding clipboard history. |
| Diagnostics & supportability (4) | 4 | Pass | Every failure path sets a specific last-error code and message, with GetLastError values included in platform errors and the contention failure naming its likely cause and attempt count; `cp_sequence` doubles as a zero-cost health probe a host can use to explain any wait behaviour. Not 5: no counters/status call exists (by design — the kit is stateless), so a host cannot introspect past calls. |

Weighted total: **84.6/100** (Correctness 11.2, Security 12.0, Robustness 8.8, Completeness 9.0, Performance 4.8, Maintainability 5.6, Modularity 6.0, UX 4.8, Scalability 3.0, Idiomatic 5.0, Test evidence 4.0, Self-documentation 4.0, Documentation 3.2, Diagnostics 3.2).

## What moves the score

1. On-machine Windows field pass (set/get round trip, a populated HDROP from Explorer, a contention drill with a holder app, one very large text payload) — raises Correctness and closes the Scalability follow-up; anything found is fixed forward with a regression test.
2. A recorded wait-latency / large-text benchmark (closes the Performance waiver).
3. Coverage measurement, or recording test-count evidence as the accepted substitute (closes the Test evidence note).
