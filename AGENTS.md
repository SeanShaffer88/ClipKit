# ClipKit — agent notes

- The ownership transfer in `set_text` is load-bearing, not a style preference: after a successful `SetClipboardData` the global block belongs to the clipboard and must NEVER be freed — freeing it corrupts the clipboard for every other app. The block is freed only on paths where the hand-off provably did not happen (alloc/lock failure, open failure, EmptyClipboard failure, SetClipboardData returning NULL). Do not "simplify" the error paths into one shared cleanup that frees unconditionally.
- Allocate before opening: `set_text` encodes and allocates its block BEFORE `ClipboardGuard::open`, so an allocation failure leaves the current clipboard contents untouched. Moving the EmptyClipboard earlier reintroduces the "failed set wipes the user's clipboard" failure.
- Every clipboard access goes through `ClipboardGuard` (retrying open, close on drop). A raw OpenClipboard/CloseClipboard pair anywhere else will eventually leak an open on an early-return path — the clipboard stays locked for the whole system while held open.
- The sequence number is compared for equality only. It is an unsigned 32-bit counter that `cp_sequence` returns bit-reinterpreted as a C int, and `parse_sequence_number` accepts the signed spelling back — that round-trip is a contract with a test on both spellings and both range ends. Do not "fix" negatives into errors, and never order-compare sequence numbers.
- `cp_wait_change` must never open the clipboard to decide: the entire point of the sequence-number design is a change check that costs nothing and contends with nobody. The decision loop in `lib.rs` takes the sequence source and the sleep as injected closures — keep platform and clock out of it so the fake-source tests stay the spec.
- A missing format is a successful empty result (`{"text": null}` / `{"files": []}`), never an error code. Conflating the two makes every caller write a "was it empty or broken?" branch against the last-error — the exact ambiguity the JSON shapes exist to remove.
- The JSON engine (src/json.rs) is the family design — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins.
- Zero dependencies; the only platform surface is src/platform.rs (user32 clipboard, kernel32 global memory, shell32 DragQueryFileW — every extern block carries its #[link]). The Windows runtime path is Unverified until a field test on a real Windows machine runs it; the pure core and the off-Windows NOT_SUPPORTED behaviour are what the local gate proves.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate.
